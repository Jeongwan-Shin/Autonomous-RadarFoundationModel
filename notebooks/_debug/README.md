# _debug — f-theta 투영을 눈으로 검증한 기록

`datatools/geometry.py` 의 `ftheta_project` 가 맞는지 확인하면서 남긴 그림입니다.
`agent_traj_bbox` 와 `det_objects_3dbbox` 의 정답이 전부 이 함수를 지나가므로,
여기가 틀리면 두 태스크의 라벨이 통째로 틀립니다.

**한 번 잘못 판단했고, 그 기록이 여기 남아 있습니다.** 안개 낀 장면에서 투영
박스를 눈으로 보고 "틀렸다"고 결론지었는데, 수치로 재보니 맞았습니다.

| 파일 | 무엇 |
|---|---|
| `projection_ok.png` | 정면 30 m → x=946 (화면 중앙 961), 좌 30° → 436, 우 30° → 1457 |
| `frames_bug.png` | 프레임 인덱스를 잘못 짚어 다른 시각의 그림에 박스를 그린 것 |
| `wrong_frame_zoom.png` | 위의 확대 — 박스가 아니라 프레임이 어긋나 있었다 |
| `agent_traj_bbox_A*.png` | 지목한 물체의 +1/+2/+3초 박스, 정상 사례 |
| `agent_traj_bbox_B*.png` | 같은 형식의 두 번째 사례 |
| `agent_traj_bbox_C_leaves*.png` | 지평선 안에 섹터를 벗어나는 사례 (`leaves the forward sector`) |

`_view` 접미사는 같은 장면을 확대한 것입니다.

**투영이 옳다는 최종 근거는 그림이 아니라 숫자입니다.** 벤더가 개인정보 보호용으로
블러 처리한 영역과 대조했더니 투영 박스 안에 들어간 비율이 89.9%, 클립당 중앙값
0.92 였습니다. 안개 낀 장면에서는 사람 눈이 신뢰할 만한 판정자가 아니었습니다.
